### Evidence 4 — Detection logic is sound

`harness-health-self-scan.sh:69-79`:

```bash
HH2_check() {
  [ ! -f "$HOOK_LOG" ] && { emit_skip "HH-2" "log-missing"; return; }
  local cutoff recent
  cutoff=$(date -d "10 min ago" -Iseconds 2>/dev/null || python3 -c "import datetime; print((datetime.datetime.now()-datetime.timedelta(minutes=10)).isoformat())" 2>/dev/null || echo "")
  [ -z "$cutoff" ] && { emit_skip "HH-2" "date-math-unavail"; return; }
  recent=$(awk -v cutoff="[$cutoff" '$0 > cutoff' "$HOOK_LOG" 2>/dev/null | grep -c "UserPromptSubmit" || echo 0)
  [[ "$recent" =~ ^[0-9]+$ ]] || recent=0
  if [ "$recent" -lt 1 ]; then
    emit_fail "HH-2-USERPROMPT-NOT-FIRING" "HIGH" "recent_10min=0"
  fi
}
```

The substring grep `UserPromptSubmit` matches:
- `UserPromptSubmit-injector: SKIP (trivial prompt detected)` (real injector emission)
- Any future hook self-emit naming `UserPromptSubmit`

This is correct. The logic does what the spec D-035 documents.

## Root-cause classification

**HH-2 false-positive condition**: harness-health-self-scan invoked under a synthesized context (smoke harness, test runner, manual cron) where:
- (a) `CLAUDE_SESSION_ID` is unset, empty, or set to a non-real value (e.g., `firing-test-smoke-NNNN`); AND
- (b) no real Claude `UserPromptSubmit` hook has fired in the prior 10 min.

In such contexts, HH-2 correctly identifies "UserPromptSubmit chain inactive" — but this is **trivially true** when the invocation itself is outside the production hook chain. It is not informative about the chain's health.

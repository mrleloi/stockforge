## Lessons learned (1 candidate; L-S16-1)

### L-S16-1: When pre-existing artifact violates D1, amend via companion file (references/), not by appending to the violating file

**Rule**: amending a pre-existing D1-violating file (skill/command/agent at >ceiling) must NOT add LOC to that file. Use `references/<topic>.md` companion (no D1 ceiling) or factor depth out before adding new content.

**Reason**: success criterion "0 new D1 violations" is hollow if amendments worsen pre-existing violations. The spirit is "this session does not increase the deficit". Skill body at 163 LOC + 25 LOC append = 188 LOC = bigger debt; that's not "no new violations", it's deeper old violations.

**How to apply**:
- If SKILL.md ≤ ceiling: append directly per Plan
- If SKILL.md > ceiling: create `references/<topic>.md` companion; ≤1 LOC reference from SKILL.md if needed
- Track 6 secondary closure (S17 candidate) is the right time to compress the violating file BELOW ceiling, then post-S17 amendments can append directly

**Anti-example**: appending 25 LOC of L-S14 best practices to write-a-skill SKILL.md at 163, producing 188 LOC. The amendment ships, the violation grows, the S16 outcome table shows "no new D1" (technically true: count stays 16) but the deficit deepens.

**Correct example (this session)**: created `.claude/skills/write-a-skill/references/best-practices.md` (42 LOC NEW) and did NOT touch SKILL.md. Count stays 16; deficit unchanged.

**Promotion candidate**: amend `proposals/architecture-amendment.md` § "When SKILL.md exceeds ceiling" subsection OR write-a-skill SKILL.md (post-Track-6-secondary). S17+ candidate.

Investigation traced root cause to a **L-S48m-1 sister bug**: hook used `SID="${CLAUDE_SESSION_ID:-main}"` then `MARKER="$MEM_DIR/.qa-auto-mv-fired-${SID}"`. On Windows, `CLAUDE_SESSION_ID` is empty for SessionStart/Stop hooks (per L-S48m-1) → fallback `"main"` shared across ALL sessions → marker `.qa-auto-mv-fired-main` created at 2026-05-05 13:14 (S48h smoke session) blocked the per-session-idempotency check on every subsequent session (S99 through S107). Existing bash-hook-lint Check 6 only catches DIRECT `$CLAUDE_SESSION_ID` in marker filename; misses indirect-via-VAR form like this.

Fix shipped:
- **T1**: Replaced SID-fallback with hour-bucket marker + cleanup loop in `qa-pending-auto-mover.sh`. Marker now `${MEM_DIR}/.qa-auto-mv-fired-$(date +%Y%m%d-%H)`. Cleanup loop deletes any non-current-bucket markers on each fire (self-recovery).
- **T2**: Extended existing firing-test from 6 TC → **7 TC**, added TC7 as L-S108-1 regression test (plants both stale Jan-2026 hour-bucket marker AND legacy "main" fallback marker → asserts both cleaned + bundle MV'd).
- **T3**: Extended `bash-hook-lint.sh` with **Check 6b (Pattern B')** — emits when file has BOTH `${CLAUDE_SESSION_ID:-WORD}` assignment AND marker filename pattern (`.foo-(fired|marker|ran|flag|written|pending)-$VAR`). Catches the indirect-via-VAR form Check 6 misses.

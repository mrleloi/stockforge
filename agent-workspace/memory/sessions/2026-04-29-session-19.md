## Lessons learned (1 candidate; L-S19-1)

### L-S19-1: deterministic Stop-hook aggregator > continuous LLM Guardian for Phase 0 telemetry rollup

**Rule**: when telemetry has well-defined deterministic features (counts, sums, grouping), implement the rollup as bash + awk Stop hook BEFORE adding any LLM aggregation. LLM dispatch only at session-end + only when telemetry signals require interpretation (e.g. anomaly detection, root-cause analysis).

**Reason**: continuous LLM Guardian projected ~50K tokens/hour idle (UP02 §1.4 explicit cost concern). Deterministic aggregator over 870 tool calls + 5 subagents emitted a useful row in <1s with 0 LLM tokens. The deterministic substrate isn't a precursor to LLM aggregation — it IS the rollup. LLM analysis layers on top when needed.

**How to apply**:
- Pre-flight when designing telemetry rollup: identify the schema fields + grouping operations.
- If groupings are deterministic (counts, sums, per-key aggregations), implement as bash + awk.
- Reserve LLM dispatch for: anomaly thresholds + cross-session pattern mining + natural-language summarization.
- Document the boundary: aggregator ships data; LLM analyst interprets data. Don't conflate.

**Anti-example**: a Stop hook that pipes raw component-telemetry.jsonl rows into an LLM prompt to produce sessions-rollup.tsv — wastes ~30K tokens for what awk does in 124 LOC.

**Correct example (this session)**: D-008 + scripts/hooks/self-awareness-aggregate.sh — Phase 0 aggregator is bash+awk; Phase 1+ telemetry-analyst LLM subagent reads sessions-rollup.tsv (already aggregated) for cross-session pattern mining only.

**Promotion candidate**: amend `proposals/architecture-amendment.md` § "Telemetry rollup design" with a Rule N "deterministic substrate before LLM" sub-clause. Or extend `decompose-work/SKILL.md` with telemetry-rollup template (count/sum/group → bash+awk; interpret → LLM).

## Lessons NEW (S174)

### L-S174-1 — Bash firing-test must use `RC=0; cmd || RC=$?` pattern when checking RED-state exit codes

**Context**: attach-portability-smoke-fire-test.sh Test 5 verified `bash $smoke; rc=$?` then asserted rc==1 for RED state. Direct invocation triggered ERR trap (set via `trap 'cleanup; exit $RC' ERR EXIT`) → premature script exit mid-test. Output cut off after first PASS line of Test 5; Summary never printed.

**Rule**: When a firing-test deliberately invokes a script expected to return non-zero (testing RED-state detection), use `RC=0; cmd || RC=$?` instead of `cmd; rc=$?`. The `|| RC=$?` form prevents ERR trap firing on the deliberate rc=1.

**Why**: `set -uo pipefail` (without `-e`) does not by itself cause script exit on simple-command failure, BUT `trap '...' ERR EXIT` fires the trap on every non-zero exit of any simple command — and our trap calls `exit $RC` which terminates the script.

**Anti-example**:
```bash
bash "$SMOKE" >/dev/null 2>&1   # rc=1 → ERR trap → cleanup → exit 1 (mid-test!)
LEAK_RC=$?                       # never reached
```

**Correct example**:
```bash
LEAK_RC=0
bash "$SMOKE" >/dev/null 2>&1 || LEAK_RC=$?   # rc=1 absorbed by ||; trap not fired
```

**Severity**: medium. **Auto-detect**: yes (grep firing-tests for `bash.*>.*2>&1$` not preceded by `|| RC=` and followed by `\$\?` — candidate hook `firing-test-rc-pattern-lint.sh`; promote-rule cycle catches).

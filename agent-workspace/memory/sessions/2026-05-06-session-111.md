## T2 — HH-H.1 stale-block marker write-only bug discovery (M-S111-1)

### Discovery

`scripts/session-self-reboot.sh` (HH-H.1 inner fence, 5min strict guard) writes `.auto-reboot-BLOCKED-stale-checkpoint` marker when checkpoint is stale (>300s) → exits 2 to refuse reboot. BUT: **no clear-on-fresh logic**. Marker persists indefinitely after underlying condition (stale checkpoint) resolves.

Sibling `scripts/hooks/auto-reboot-handoff-verify.sh:64` (HH-H.4 outer fence, 2h soft guard) has the correct pattern:
```bash
if [ "$STALE_AGE_S" -le "$STALE_THRESHOLD_S" ]; then
  # Checkpoint is fresh; clear any prior pre-block marker so watchdog can fire normally.
  rm -f "$PRE_BLOCK_MARKER"
  exit 0
fi
```

HH-H.1 was missing the equivalent clear path. Result: stale orphan markers accumulate on disk and surface as ghost diagnostic state.

### Severity: LOW

- The marker has no active CONSUMER (nothing reads `.auto-reboot-BLOCKED-stale-checkpoint`; it's write-only).
- HH-H.1 guard re-evaluates from CHECKPOINT mtime each invocation; the marker's presence does NOT block subsequent reboot attempts (unlike HH-H.4's PRE-BLOCK marker which IS consumed by budget-watchdog.sh:78).
- Bug surface: cosmetic git-status noise + diagnostic confusion (urgent.md content references "marker `.auto-reboot-PRE-BLOCKED-stale-checkpoint`" — adjacent but distinct marker name).

Different RCA from M-S108-1 (which was per-session-fallback collision); this is missing-clear-path.

### Fix

`scripts/session-self-reboot.sh` Edit (~4 LOC): add comment + `rm -f "$STALE_BLOCK_MARKER"` immediately after the guard `fi`. Both branches (FORCE_REBOOT=1 + non-FORCE-fresh-checkpoint) reach this line; both clear the marker. The stale-checkpoint branch exits 2 BEFORE reaching this line (preserving marker on actual abort).

### Smoke test (3 TC manually)

| TC | Setup | Expected | Result |
|---|---|---|---|
| TC1 | Plant marker + STOCKFORGE_FORCE_REBOOT=1 | Guard skipped → marker cleared post-fi | PASS |
| TC2 | Plant marker + checkpoint fresh (touch now) | Guard passes → marker cleared post-fi | PASS |
| TC3 | Plant marker + checkpoint 600s old | Guard aborts → marker preserved (script exit 2) | PASS |

### Side-effect cleanup

Deleted on-disk `.auto-reboot-BLOCKED-stale-checkpoint` (the 8h-old orphan); git status now shows `D` for the path. Git tracking of the file itself remains a STRUCTURAL ISSUE (file should be `.gitignore`'d like `.auto-reboot-FAILED` is at .gitignore:73 + 82) — filed as backlog item below.

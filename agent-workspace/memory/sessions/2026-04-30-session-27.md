## Decisions

### IMPL-S27-1 — Shared-kernel relocation (Ticker/Money/Enums/Ids → contracts/types/)

**Tier**: IMPL (master-plan path adjustment downstream of architecture.md constitutional rule).

**Issue**: master-plan 004 § S27 deliverables #1-3 placed `Ticker`, `Money`, `AdjustmentType`, `SourceProvider` in `packages/domain/market_data/value_objects/`. But architecture.md § Cross-BC Rules states "Never direct import between BCs. Cross-BC types live in `packages/contracts/`." BC-9 `Position.ticker: Ticker` and `Position.avg_cost: Money` would force a direct cross-BC import.

**Resolution**: Shared-kernel pattern — relocated VOs to `packages/contracts/types/`. BC-1 imports them via `from packages.contracts import ...`. BC-9 imports the same way. No cross-BC import occurs.

**Why not Option A (folded into BC-1, BC-9 imports BC-1)**: violates architecture.md cross-BC rule explicitly. The rule is canonical (constitution-tier); master-plan abstraction must yield to constitution-tier authority.

**Why not Option B (duplicate VOs in each BC)**: violates DDD ubiquitous-language single-source-of-truth; would silently allow Ticker(VHM) ≠ Ticker(VHM) across BC boundaries because they'd be different types.

**Source evidence**: architecture.md § Cross-BC Rules; CLAUDE.md hard rule "Cross-BC communication via contracts only"; agent-workspace/CLAUDE.md Contract Rule (architecture is constitution-tier).

### IMPL-S27-2 — Cross-BC PriceSnapshot value object introduction

**Tier**: IMPL (additional ARCH detail surfaced post-IMPL-S27-1).

**Issue**: After IMPL-S27-1, `Position.current_value()` still imported `Bar` from BC-1 directly (because the master-plan signature was `current_value(latest_bar: Bar)`). Re-running cross-BC grep flagged this as a violation.

**Resolution**: Introduced `packages/contracts/types/price_snapshot.py` as a small cross-BC value object carrying `(ticker, close, as_of, bar_id)`. BC-1 `Bar` exposes `Bar.to_snapshot()` projection. BC-9 `Position.current_value(snapshot: PriceSnapshot)` consumes the contract type — never imports Bar.

**Why not embedded primitives** (close: Money, as_of: date, bar_id: BarId, ticker: Ticker as 4 args): loses the cohesive "this is a price quote at a moment" semantics; harder to evolve when Phase 2 adds bid/ask/last fields.

**Why not anti-corruption layer** (BC-9 maintains its own MarketPrice VO + adapter): overkill for thin-slice; PriceSnapshot is a shared-kernel-style contract that both BCs trust to be stable.

**Source evidence**: architecture.md § Cross-BC Rules + § Cross-BC events example (`KolRecommendationExtracted` carries `Ticker`); spec 000 § B.3 Domain Events.

**Tier**: IMPL (deterministic-gate observability gap — non-blocking for IMPL).

**Issue**: success criteria #3 + #4 require `mypy --strict` and `ruff check` to exit 0. Both tools are declared in `pyproject.toml` dev dependencies but not currently installed in the Python env active for S27.

## Critical discovery + surgical fix (D-S10-1)

**Pre-existing bug discovered**: `scripts/hooks/component-telemetry.sh` had **silently failed every invocation since shipping S8** (Track 5.5c.5 JSONL telemetry).

**Root cause**: `set -uo pipefail` + `trap 'exit 0' ERR` + `[ x ] && Y` patterns at lines 111, 124, 226 trip ERR trap when LHS is FALSE (Git Bash on Windows behavior; conditional-context exemption doesn't appear to apply here). Plus `local session="$1" ts_file="...${session}"` at line 115 trips `set -u` because `session` is unbound at parse-time of `ts_file` (same-line-local-variable-cross-reference).

**Symptom**: `agent-workspace/memory/component-telemetry.jsonl` did NOT exist on disk despite the hook being wired in `.claude/settings.json` since Track 5.5c.5 ship date. **Silently bricked telemetry stream for ~3-4 sessions of "shipped" claim**.

**Fix applied (4 lines)**:
- Line 111: `[ "$TOKENS_REAL" -lt 0 ] && TOKENS_REAL=0` → `if [ "$TOKENS_REAL" -lt 0 ]; then TOKENS_REAL=0; fi`
- Line 115: `local session="$1" ts_file="..." now=0 prev=0` → split into 3 separate `local` declarations (resolves `set -u` cross-reference).
- Line 124: `([ x ] || [ y ]) && Z=0` → `if [ x ] || [ y ]; then Z=0; fi`
- Line 226: `[ x ] && Y` → `if [ x ]; then Y; fi`

**Validation**: After fix, both telemetry streams are LIVE:
- `agent-workspace/memory/component-telemetry.jsonl` populates on every PostToolUse (verified via real session events captured during S10 close).
- `agent-workspace/learning-data/events/2026-04-29.ndjson` populates with new schema (ts/source/event_type/payload/as_of).

**Rationale for in-scope fix**: D-2 success criterion ("component-telemetry.sh smoke-test emits parseable NDJSON learning event") cannot be met if the parent hook is bricked. 4-line surgical fix vs deferring to S11 = pragmatic + restores both streams. ## Lessons learned (potential agent-notes promotions)

### L-S10-1: ERR-trap silent failure pattern (set -uo pipefail + trap ERR + bash conditional)
**Context**: component-telemetry.sh + dispatch-jsonl-recorder.sh both use `set -uo pipefail` + `trap 'exit 0' ERR` + `( ... ) </dev/null >/dev/null 2>&1 &` subshell pattern. component-telemetry was bricked silently because of ERR-trap interactions with `[ x ] && Y` and `local A=B B=$A` patterns. dispatch-jsonl-recorder happens to NOT have those patterns and works.
**Rule**: Bash hook scripts MUST use `if/then/fi` and split-`local` declarations when running with `set -uo pipefail` + `trap ERR`. Single-line `[ x ] && Y` and same-line cross-referenced `local` are unsafe. When porting orch v2.2.0 hook scripts, scan for these patterns.
**Severity**: HIGH (silent failure = no observability; bricked stream for 3+ sessions).
**Promotion**: candidate for `scripts/hooks/loc-ceiling-check.sh` (or new `bash-hook-lint.sh`) — drift signal scanning all hook scripts for these anti-patterns. Prevents future ports.

### L-S10-2: Glob honors .gitignore (boundary enforcement bonus)
**Context**: After gitignore'ing `learning-data/events/` + `archive/`, Glob returned "No files found" even though .ndjson files existed on disk. Agent-as-runtime cannot enumerate gitignored paths.
**Rule**: For write-only / runtime-deny boundaries, gitignore + permission deny + drift signal D9 give triple-enforcement. The first 2 are zero-cost; D9 is +25 LOC scan.
**Severity**: low (validation of design intent).
**Promotion**: not promotable yet — single observation; promote if pattern recurs.

### L-S10-3: Permission deny on Read(path) intersects bash file ops
**Context**: `Bash(cat:*)`, `Bash(wc:*)`, `Bash(find:*)` are all in allow list. Yet running `cat learning-data/events/X.ndjson` gets denied because Read(path) deny applies across the harness.
**Rule**: Permission deny rules on file paths block all read-side tool families (Read, Glob enumeration, Bash file ops). Useful for boundary discipline. When designing access boundaries, deny on the path is sufficient — no need to enumerate per-tool denies.
**Severity**: low (informational).
**Promotion**: candidate for `agent-workspace/constitution/boundaries.md` documentation (Track 7 S15).

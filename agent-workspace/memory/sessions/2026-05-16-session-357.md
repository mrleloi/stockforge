## Mistake Log

**M-S357-1 IMPORTANT (inline-resolved)**:
- What: Plan assumed VietnamBiz `meta[article:published_time]` datetime string could be treated as UTC when no timezone present (docstring said "attach UTC"). Actual site: `2026-05-16T16:33:00` (no +07:00, unlike Vietstock). Naively attaching UTC would make published_at=16:33 UTC > ingested_at=~09:33 UTC, violating Rule 8.
- Root cause: Architect plan estimated "treat as UTC (conservative)" which is factually wrong for Vietnam local times. VN local time is UTC+7, so 16:33 VN = 09:33 UTC.
- Fix: Applied `_TZ_VN = timezone(timedelta(hours=7))` throughout `_parse_published_at`. CLI smoke confirmed article ingested correctly post-fix.
- Severity: IMPORTANT (would have caused Rule 8 invariant failure on every article if not caught)
- Prevention: For any VN site where meta datetime has no tz suffix, apply UTC+7 (Vietnam has no DST). Document this in STEP 0 findings.

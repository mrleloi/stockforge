## IMPL-tier decisions made (per D-003 § Open Questions doctrine)

### IMPL-S13-1: failure_mode codes expanded from 3 (A/B/C) to 8 (A/B/C/D/H/P/T/null)

**Discovery**: Original code set in component-telemetry.sh was `narration_hit=A` / `api_error=B` / `premature_windown=C` correlated from a non-existent log file, plus `H` set at dispatch site for deny. Patterns in real producers (`.session-hooks.log` writes `CLIFF tokens=`; `.autonomous-premature-windown-alert.log` writes `MODE-C GUARD BLOCKED`) didn't match any of the 3 correlate keys. Plus actual telemetry has `outcome` values (`error` / `timeout` / `reject`) that should ALSO drive failure_mode.

**Decision**: 8-code set: A=reserved (LLM-side; not wired) / B=outcome-error / C=mode-C correlate / D=reserved (drift-threshold; not wired due to constant fire today) / H=permission-deny (override) / P=cliff-fire correlate / T=outcome-timeout / null=default. Document in jsonl-schema.md § Failure mode codes. Override ordering: correlate → outcome-fallback → deny-override.

**Rationale**: deterministic + falsifiable + observability-rich. Trade-off accepted: 8 codes vs original 3 means classifier prompt grows, but classifier already needs to handle 5 buckets so the marginal cost is small. Reserved A/D codes preserve room for future LLM-side detectors without re-numbering.

**D-003 amendment carry-over**: surface for D-003 § 5.5c.5 prose at S15 (Track 7) D-003 amendment.

### IMPL-S13-2: OTEL stack descoped to design-only at Phase 0 per L-S11-1

OTEL adds value at Phase 2+ multi-service deployments; deferring until then is correct-deferral, not over-engineered descope.

### IMPL-S13-3: Cumulative metric default with windowed deferred to S14

**Discovery**: S12 Karpathy framing target was "≥8.3% on next 60-event corpus" (windowed). S13 metric script defaults to cumulative over all events (337 total). Cumulative 2/337=0.59%; sample-windowed 2/100=2.0%. Both miss the 8.3% target. The two interpretations diverge sharply at wire-in boundary because pre-wire-in events bias cumulative toward 0% (all 60 S11 events have null because wire-in didn't exist yet).

**Decision**: S13 ships cumulative as default. `--window N` argument deferred to S14 (carry-over). Document the distinction in agent-notes (L-S13-2 entry).

**Rationale**: scope-tight at S13; the comparison is structural (does failure_mode populate at all?) not magnitudinal (is the rate above 8.3%?). DEEPEN structurally confirmed. Magnitude verdict deferred to S14 once natural failure events accumulate. Safer than gaming the metric by force-firing synthetic events.

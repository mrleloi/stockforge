# Phase 3.5 — Harness Deepening (Empirical-Firing Discipline)

## Why this phase exists

**Phase 2.5 verdict (8/8 GREEN, S49a audit)** was a ritual-completion verdict, not an empirical-firing verdict. Audit checked "hook script exists + wired in settings.json + smoke command exits 0" — it did NOT check "hook actually fires on the events it claims to gate". M-S49b-1 surfaced this gap: `autonomous-stop-watchdog.sh` is wired in Stop chain + smoke-test passes when invoked manually, BUT logs show 0 `Stop session=` entries across ~10 turns of session 5b96635e. Production telemetry contradicts the ritual verdict.

**Three empirical failures surfaced ONLY via user push (post-audit-close)**:
1. **M-S49b-1**: Stop hook 0 fires for current session despite being wired. Manual invocation works. Suspected Claude Code 4.x Windows quirk under unknown conditions.
2. **Promote-rule backlog**: Last run S43c (2026-05-04). Now S49b. ~6+ sessions accumulated agent-notes entries without promotion cycle running. `promotion-cycle-trigger.sh` exists but did not fire (likely Stop-hook-dependent — see #1).
3. **Auto-detect candidates without companion shipped hook**: ~20 entries in agent-notes tagged `Auto-detect: yes` that never got promoted to actual deterministic hook. Visible only via manual grep, not via any harness alarm.

**Anti-pattern codified**: "ritual completion without empirical-firing verification". Counter-rule (T8 ratification target): **"Harness must self-verify firing, not self-attest existence"**.

**Confidence assessment**: Phase 2.5 "post-audit" autonomous-readiness was claimed ~7/10. Real production behavior is ~5/10 (defects surfaced via user, not self-detected). After Phase 3.5 close: target ~8.5/10 with empirical evidence backing every claim.

## Hard rules during Phase 3.5

1. **Each track = separate session** per CLAUDE.md never-mix-PLAN-with-IMPL doctrine. Multi-track-IMPL allowed only when tracks are mechanically independent (T2 + T6 are; T3 needs T2 done first).
2. **Every hook authored in this phase MUST ship with a companion firing-test** (T7 retrofit codifies this rule). Firing-test = bash script that triggers the hook's gate event in a controlled fashion + asserts the hook produced the expected log/file artifact. Unit-test of script logic is NOT enough — empirical fire required.
3. **No silent re-attestation**. If a track marks "DONE" but T6 harness-health-self-scan signals FAIL on its self-check, the track is NOT closed; root-cause first.
4. **VBW pre-flight Glob-before-Read** on every target file edit (L-S30-1 doctrine).

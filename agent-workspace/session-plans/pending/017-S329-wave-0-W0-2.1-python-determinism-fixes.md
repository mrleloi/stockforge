**Why this fix is correct**:

### D2 — Fix R2 (`random.sample(...)` in production path)

**File**: `packages/application/crowd/use_cases/capture_sentiment_snapshot_use_case.py`
**Line**: 180

**Decision required**: this plan recommends **"inject seeded `random.Random` instance via constructor"** (Approach A below). The dev MUST execute Approach A unless STEP 0 surfaces blocking evidence (e.g., the use case is already exercised by Hypothesis property tests that would conflict with a constructor-injected RNG); in that escalation case, dispatch back to main with a single-paragraph rationale + plan deviation request.

**The 3 approaches considered**:

| # | Approach | Pros | Cons | Verdict |
|---|---|---|---|---|
| **A (RECOMMENDED)** | **Inject `random.Random` instance via constructor** (parallel to existing `clock: Callable[[], datetime]` field at lines 113-115). Default-factory = `random.Random()` (unseeded singleton). Replace line 180's `random.sample(...)` with `self._rng.sample(...)`. Tests construct with explicit seed: `rng=random.Random(42)`. | (a) Mirrors the existing `clock` injection pattern at lines 113-115 (architectural consistency). (b) Tests get bit-exact determinism with explicit seed. (c) Default behaviour preserved for production callers who don't care. (d) `random.Random` is an instance — `random.Random.sample()` is NOT detected by R2 (the detector at `scripts/hooks/python-determinism-check.sh:165-185` matches `random\.(random\|randint\|choice\|shuffle\|sample)\(` against the MODULE — instance-method calls don't match because the dot-LHS is `self._rng`, not `random`). | (a) Adds 1 dataclass field + import. (b) 1 caller-construction site (`apps/cli/` if any) may need to be aware of the new field — but it has a default-factory so old call sites still work. | **CHOSEN** — preserves I-S1 deterministic-numbers invariant via explicit seed in tests; matches existing dependency-injection convention; smallest blast radius. |
| B | Wrap line 180 in `if __name__ == "__main__":` guard | (a) Trivial 1-line wrapper. | (a) Makes no sense — the surrounding code is the `execute()` method of `CaptureSentimentSnapshotUseCase`, called from real production paths (`apps/cli/`), not module-level. `if __name__ == "__main__"` block is for script bottoms. Wrapping a method body in this guard is semantically wrong + would break the use case. | **REJECTED** as miscomprehension of D-059 § R2's `__main__` exception. |
| C | `sorted(classified, key=lambda p: hash(p.post_id))[:20]` (deterministic by-hash sampling) | (a) No new field. (b) Bit-exact deterministic without seed. | (a) `hash()` randomized via `PYTHONHASHSEED=random` on Python ≥ 3.3 — not actually deterministic across processes. (b) Changes semantic from "20 random" to "first 20 by hash" — needs spec review. (c) Doesn't match the R2 detector exception clauses; no architectural benefit over A. | **REJECTED** for PYTHONHASHSEED issue (would be an R3 cousin violation). |

**Why A is the right call**:
- The `capture_sentiment_snapshot_use_case.py` file ALREADY uses constructor-injected determinism for time (`clock: Callable[[], datetime]` lines 113-115 with default-factory). Adding `rng: random.Random` parallel to it is the architecturally-consistent move.
- D-059 § R2 "Allowed contexts" (line 154 of the ADR) lists "test fixtures may use explicit seeds" as an explicit acceptance criterion. Approach A operationalizes this: production default unseeded, tests inject seed.
- The detector at `python-determinism-check.sh:172-179` is a regex over `random\.(random\|randint\|choice\|shuffle\|sample)\(` against the literal module name — `self._rng.sample(...)` does not match. R2 will clear.

**The edit** (D2 step-by-step):

1. **Import addition**: line 23 already has `import random`; keep that single import.
2. **Dataclass field addition** — add after line 115 (`clock` field):
   ```python
   rng: random.Random = field(
       default_factory=random.Random  # unseeded by default; production callers don't care
   )
   ```
3. **Line 180 replacement**:
   ```python
   # BEFORE
   sample_ids = [p.post_id for p in random.sample(classified, min(_MAX_SAMPLE_POSTS, len(classified)))]
   # AFTER
   sample_ids = [p.post_id for p in self.rng.sample(classified, min(_MAX_SAMPLE_POSTS, len(classified)))]
   ```
4. **Module-level `random` usage check**: after edit, the only `random` reference in the file should be the `import random` at line 23 + `random.Random` (class name) in the field annotation/default-factory. The R2 detector regex `random\.(random\|randint\|choice\|shuffle\|sample)\(` will NOT match either reference (`random.Random` ends in capital R — class name, not method). Detector clears.

**Sketch** (NOT FOR EXECUTION in this PLAN session — the dev authors this in S329):
```python
def test_rebuild_thesis_fallback_uses_utc_aware_datetime(repo: SqliteThesisRepository) -> None:
    """When persisted created_at is malformed (non-string), fallback default must be UTC-aware (R1 fix)."""
    thesis = _make_thesis("fallback-001")
    asyncio.run(repo.save(thesis))
    # Force malformed payload (simulate persisted JSON corruption)
    with closing(sqlite3.connect(repo.db_path)) as conn:
        # Replace created_at field in payload_json with a non-string sentinel
        cur = conn.execute("SELECT payload_json FROM theses WHERE thesis_id=?", ("fallback-001",))
        row = cur.fetchone()
        assert row is not None
        payload = json.loads(row[0])
        payload["created_at"] = None  # force the line-206 else-branch
        conn.execute(
            "UPDATE theses SET payload_json=? WHERE thesis_id=?",
            (json.dumps(payload), "fallback-001"),
        )
        conn.commit()
    retrieved = asyncio.run(repo.get_by_id("fallback-001"))
    assert retrieved is not None
    assert retrieved.created_at.tzinfo is not None, "R1 fix: fallback datetime must be tz-aware"
    assert retrieved.created_at.tzinfo == timezone.utc, "R1 fix: fallback datetime must be UTC"
```

```python
def test_snapshot_sample_ids_deterministic_when_rng_seeded(self) -> None:
    """Seeded RNG produces reproducible sample_ids (R2 fix)."""
    import random as random_module
    posts = [_make_raw_post(f"p{i}") for i in range(25)]
    classified = [_make_classified_post(f"p{i}", Sentiment.BULLISH) for i in range(25)]
    # First run with seed 42
    uc1, _ = self._build_use_case(posts, classified, coord_score=0.1)
    uc1.rng = random_module.Random(42)
    snap1 = uc1.execute("VND", Window.ONE_HOUR)
    # Second run with same seed 42
    uc2, _ = self._build_use_case(posts, classified, coord_score=0.1)
    uc2.rng = random_module.Random(42)
    snap2 = uc2.execute("VND", Window.ONE_HOUR)
    assert snap1.source_posts_sample == snap2.source_posts_sample, \
        "R2 fix: same seed must produce identical sample order"
    # Different seed → different sample (anti-hardcoded sanity check)
    uc3, _ = self._build_use_case(posts, classified, coord_score=0.1)
    uc3.rng = random_module.Random(99)
    snap3 = uc3.execute("VND", Window.ONE_HOUR)
    assert snap1.source_posts_sample != snap3.source_posts_sample, \
        "R2 fix: different seed must produce different sample order"
```

**Why this test**: pins the R2 fix; the assertion "seeded RNG → identical sample" is the operational seed-reproducibility guarantee D-059 § "What is Guaranteed Seed-Reproducible" line 109 promises ("Thesis ranking order — all sorting keys must be deterministic").

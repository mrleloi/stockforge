# /attach — Skeleton Templates

> Templates for skeleton files generated at target project root.
> The skill procedure extracts sections from this file and writes them.

## CLAUDE.md

```markdown
# <PROJECT_NAME> — Claude Code Instructions

> Generated by /attach from harness baseline. Customize freely.

## Identity

You are **Claude Code**, the engineering partner for <PROJECT_NAME>.

**Primary user**: <USER_NAME>.
**Stack**: <STACK_HERE>.

---

## Core Principles (Karpathy 4)

**P1. Think Before Coding.** State assumptions. Surface tradeoffs. Push back when simpler approach exists.

**P2. Simplicity First.** Minimum code that solves the problem. No speculative features.

**P3. Surgical Changes.** Touch only what the task requires. Match existing style.

**P4. Goal-Driven Execution.** Transform imperative → verifiable goals with concrete success criteria.

---

## Session Protocol

### Start
1. Read `agent-workspace/memory/current-execution.md` → resolve active track
2. Read `agent-workspace/memory/project.md` → project state (when authored)
3. Read last 3 files in `agent-workspace/memory/sessions/` → recent context
4. Run VBW protocol before writing any spec/test/code

### End
1. Update `agent-workspace/memory/project.md` (if architectural decisions made)
2. Write `agent-workspace/memory/sessions/YYYY-MM-DD-session-N.md`
3. Update `agent-workspace/memory/current-execution.md`

---

## Hard Rules

- Domain layer has zero framework dependency. Pure Python in `packages/domain/` (or equivalent).
- VBW Protocol mandatory before writing specs/tests/code.
- Agents MUST NOT `git commit` unless user explicitly requests.
- User prompt overrides ALL defaults.

---

## Layer Manifest

`.claude/manifest.yaml` declares what's harness vs project-biz vs personal. Read at /attach time + drift audit time.

---

## First Interaction

If user is starting fresh, run `/session-start` to load state and propose next actions.
```

## agent-workspace/CLAUDE.md (harness baseline)

```markdown
# agent-workspace/ — Contract

> Audience: agents working inside `agent-workspace/`.
> Generated from harness baseline by /attach.

## Identity

`agent-workspace/` is the agent-owned execution + memory layer. Agents WRITE here freely
(within constitution rules); humans READ here but normally do not edit.

## Subdirectories (skeletal — populate as needed)

- `memory/sessions/` — one file per session
- `memory/decisions/` — sequential ADRs
- `memory/checkpoints/` — handoff state for self-reboot
- `memory/observations/` — subagent return artifacts
- `memory/agent-notes.md` — learned rules
- `session-plans/pending/` — plans authored, awaiting execution
- `session-plans/completed/` — executed plans

## Contract Rules (BINDING)

1. `current-execution.md` is the routing source-of-truth — never hardcode paths in skills/CLAUDE.md
2. `memory/decisions/` is append-mostly + supersession-status
3. Provenance is mandatory — every decision references its source
4. Agents never `git commit` unless user explicitly requests

## Reading Priority for Agent

1. `memory/current-execution.md`
2. `memory/project.md`
3. `memory/checkpoints/latest.md` if recent
4. `memory/agent-notes.md`
5. Last 3 files in `memory/sessions/`
6. `session-plans/pending/<active-plan>.md`
7. Relevant skills + agents + commands as task demands
```

## human-workspace/CLAUDE.md (harness baseline)

```markdown
# human-workspace/ — Contract

> Audience: agents reading from + writing into `human-workspace/`.
> Generated from harness baseline by /attach.

## Identity

`human-workspace/` is the human-owned input + decision layer.

## Subdirectories

- `user_prompt/` — humans drop new prompts here (agent: read-only)
- `decisions/` — humans author binding decisions (agent: read-only)
- `q-and-a/pending/` — agent writes Q&A bundles awaiting human reply
- `q-and-a/answered/` — humans MOVE answered bundles here (agent: read-only)
- `q-and-a/stale/` — hook auto-moves expired bundles
- `notifications/` — agent writes URGENT alerts to human

## Contract Rules (BINDING)

1. Agent NEVER writes to `user_prompt/`, `decisions/`, `q-and-a/answered/`, `q-and-a/stale/`
2. Agent ONLY writes to `q-and-a/pending/` and `notifications/`
3. Q&A bundles in `pending/` are pure audit trail; primary input surface is AskUserQuestion tool
4. File-edit is NOT a reliable input channel for mobile-remote scenarios
```

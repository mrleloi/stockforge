# Preface

> *"The harness is not a feature. It is the substrate on which features exist."*
> — Operating principle, StockForge project

## What This Book Is

This is the operating manual for the **StockForge Harness Framework** — the multi-layer system that turns Claude Code from "an LLM with file tools" into a disciplined, self-monitoring engineering team.

The harness is what runs *around* Claude. It governs:

- **What gets loaded** when a session starts.
- **What rules are enforced** when the agent tries to write a file.
- **What gets remembered** when a session ends.
- **What gets escalated** when something looks wrong.
- **What gets verified** before any change ships.
- **What gets improved** when the same mistake happens twice.

Strip the harness away and you have an LLM that hallucinates, drifts off-spec, forgets context, repeats failures, and silently destroys work. Layer the harness on and you have an autonomous engineering loop that compounds.

This book documents every layer.

## What It Is Not

This book does *not* teach:

- How to use Claude Code (read the official docs at `https://docs.claude.com/en/docs/claude-code`).
- How to build StockForge as a product (read [`PROJECT_CHARTER.md`](../../../PROJECT_CHARTER.md)).
- How to invest in Vietnamese stocks (the harness is the framework; investment logic lives in `packages/`).

This book is *about the framework*. Treat it the way you'd treat the [Rails Guides](https://guides.rubyonrails.org/) or the [Django docs](https://docs.djangoproject.com/) — a reference you read once cover-to-cover when you join the team, then return to whenever you need to extend the system.

## Why a Book Instead of READMEs

The harness has, at last count (2026-05-19):

- **17** constitution files (immutable rules)
- **24** skills (auto-discoverable procedures; includes `harness-docs-maintainer` added with this book)
- **17** slash commands (user-invocable shortcuts; includes `/harness-docs`)
- **15** subagents (fresh-context worker personas; includes `harness-docs-auditor`)
- **~113** hook scripts (deterministic event handlers; count fluctuates as hooks evolve)
- **~114** companion firing-tests
- **6** distinct memory subsystems
- **3** quality gate tiers
- **2** workspaces (agent + human) with explicit communication channels
- **8** session types with different budgets and rituals
- **23** named anti-patterns (AP-1 through AP-23)
- **12** harness-health signals (HH-1 through HH-12)
- **12** drift signals (DR1 through DR12)
- **78+** architecture decision records (ADRs)

These pieces are not independent. A skill calls a subagent, which writes an observation, which a hook reads, which fires an escalation, which respects a constitution rule, which traces back to an ADR. Reading just the README files would leave you with vocabulary but no model.

The book unifies the vocabulary into a model.

## How This Book Was Built

This book is itself a harness artifact. It was generated by:

1. Five parallel research agents auditing the live system (skills, commands, subagents, hooks, constitution, memory, lifecycle, quality, workspace).
2. One research agent surveying documentation patterns from Rails, Django, Spring, Kubernetes, Terraform, Next.js, and the [Diataxis](https://diataxis.fr/) meta-framework.
3. Synthesis by the main session into a Diataxis-shaped table of contents.
4. Authoring chapter-by-chapter with real artifacts cited by file path.
5. Verification pass against the actual codebase.

A companion skill, [`harness-docs-maintainer`](../../.claude/skills/harness-docs-maintainer/SKILL.md), keeps this book in sync with the live harness. When you add a skill, hook, or subagent, run `/harness-docs sync` and the maintainer scans for drift between the book and reality. (See [Chapter 14 — Contributing](14-contributing.md#keeping-the-book-in-sync).)

## A Note on Honesty

This is documentation for a *real* system that the project owner uses every day. It is not aspirational. Where the system is good, the book says so. Where the system is overengineered, undocumented, or carrying technical debt, the book says so too.

Specifically, this book points out:

- Hooks that exist but have caught zero failures in months ([ritual demotion candidates](10-self-improvement.md#ritual-demotion)).
- Constitution rules that contradict each other in edge cases.
- The 23 anti-patterns we have caught ourselves committing.
- ADRs we have superseded and why.

Treat these as the system's most valuable lessons. A framework's failures are more instructive than its features.
